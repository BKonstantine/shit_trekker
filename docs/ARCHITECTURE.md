# Архитектура ShitTracker

## Развёртывание и взаимодействие

```text
Браузер (компьютер / телефон)
   | HTTPS
   v
Cloudflare Tunnel (предлагаемый способ внешнего доступа)
   |
   v
Repka Pi 3 (2 ГиБ RAM)
   |- Статический React SPA через веб-сервер
   |- Express 5: маршруты /api на том же домене
   |- SQLite и серверные сессии на постоянном диске
   `- Плановые резервные копии БД (на сервере)
```

При использовании Cloudflare Tunnel не открывать входящие порты роутера без необходимости. Общий origin для SPA и `/api` упрощает работу с CORS. Для маршрутов SPA, не относящихся к API, нужен fallback на `index.html`. Файл SQLite нельзя раздавать клиенту.

## Структура монорепозитория

```text
shittracker/
├── AGENTS.md
├── docs/
├── apps/
│   ├── web/                # React + TypeScript + Vite + Ant Design + FSD
│   └── api/                # Node.js + Express + Drizzle + SQLite
├── packages/
│   └── shared/             # DTO, перечисления и Zod-контракты
├── infra/                  # конфигурация развёртывания, когда потребуется
├── .github/workflows/      # CI/CD на следующих этапах
├── pnpm-workspace.yaml
├── package.json
└── pnpm-lock.yaml
```

В `pnpm-workspace.yaml` указываем `apps/*` и `packages/*`; внутренние зависимости объявляем через `workspace:*`. Версию pnpm закрепляем через `packageManager` и/или Corepack; в CI используем `pnpm install --frozen-lockfile`.

## Границы ответственности
- Только Express обращается к базе и определяет владельца данных по серверной сессии.
- Frontend получает DTO, не зависит от SQL-/Drizzle-схем и не знает внутреннего устройства хранилища паролей/сессий.
- `packages/shared` не зависит от среды выполнения: содержимое должно быть безопасно для импорта в браузер, без Node-only модулей.
- Для MVP не нужны SSR, микросервисы, очереди сообщений, Redis и другие тяжёлые постоянные процессы.
- В production сервер раздаёт заранее собранный frontend и запускает API только с необходимыми runtime-зависимостями. Совместимость нативного SQLite-драйвера с ОС и ARM Repka Pi проверяется **до** выбора способа сборки и доставки приложения.

## Безопасное развёртывание
- Не открывать приложение в интернет, пока не реализованы вход, безопасность сессий, защита от CSRF и тесты изоляции пользователей.
- Домен, токены туннеля и пароли не хранятся в Git.
- Желательно сохранять возможность отката артефактов релиза; перед миграциями схемы SQLite делать резервную копию.
