# Решения и открытые вопросы

Этот документ отделяет **утверждённые пользователем решения** от **предложений по реализации**. Не превращай предложение в обязательное требование без согласования.

## Утверждено
- Продукт — ручное объединение задач из разных источников, названия которых задаёт пользователь.
- MVP — список задач, поиск, фильтрация по источнику/статусу, сортировка по дедлайну; создание/редактирование/удаление и быстрая смена статуса.
- **Дедлайн обязателен**, только дата. Прошедшие дедлайны разрешены; просроченные незавершённые задачи выделяются, но их статус не меняется автоматически.
- Статусы: `new`, `in_progress`, `done`. Разрешены любые переходы.
- Источник можно создавать и редактировать; поля: ID, название, иконка. Каждый источник принадлежит одному пользователю.
- Несколько пользователей; **самостоятельной регистрации нет**. Учётные записи вручную создаются в БД через безопасную CLI-команду; вход обязателен.
- Каждый пользователь видит **только свои задачи и источники**. Общих задач нет. Администратор управляет учётными записями, но не получает доступа к чужим задачам через UI.
- Интерфейс тёмный с сиренево-фиолетовыми акцентами; слева сайдбар источников со счётчиками, на десктопе таблица, на телефоне удобное мобильное представление. Breadcrumbs и вкладки рабочих пространств удалены.
- Удалён UI экспорта/импорта, как и уведомление о локальном хранении данных.
- Frontend: React + Vite + TypeScript, Ant Design с кастомной темой, архитектура FSD.
- Backend: Express (не Fastify/NestJS), SQLite + Drizzle, Zod.
- Монорепозиторий на pnpm workspaces с общим пакетом контрактов; без Nx/Turborepo.
- Хостинг на Repka Pi 3 с 2 ГиБ RAM; доступ с телефона должен работать **вне дома**, через интернет.
- Рабочий язык проектных инструкций и объяснений для Codex — **русский**.

## Предлагаемые значения по умолчанию (проверить перед реализацией)
- Cloudflare Tunnel для публичного HTTPS. Конкретный домен, DNS, ARM-дистрибутив и способ запуска службы пока не проверены.
- Серверные сессии в SQLite, защищённые HttpOnly-cookie и безопасная авторизация; библиотеки выбрать перед реализацией.
- Дедлайн хранить как текст `YYYY-MM-DD`, время создания/обновления — UTC.
- Запрещать удаление источника с привязанными задачами, возвращая `409`.
- Счётчики: у источников — число задач не в `done`; у «Все задачи» — общее количество.
- Сортировка задач по умолчанию — ближайший дедлайн; выполненные видны, пока не скрыты фильтром.
- Резервные копии SQLite на сервере, не через интерфейс пользователя.
- React Query использовать только если он реально упростит интеграцию с API, а не устанавливать ради каркаса.

## Ещё не решено
- Точная ОС, архитектура и версии Node.js/контейнерной среды на Repka Pi; домен и учётные данные развёртывания.
- Библиотеки сессий и хеширования паролей; безопасный порядок создания первого администратора.
- Пути к БД и резервным копиям на устройстве, срок хранения копий и процедура восстановления.
- Лимит пользователей и необходимость CLI для сброса пароля/отключения учётной записи (эту функциональность можно оставить только в CLI).
- Нужно ли требовать источник для **каждой** задачи (в UX-проекте рекомендовано «да»; уточнить, если позже появятся задачи без источника).
- Точная стратегия пагинации/сортировки API и язык поиска; первая версия должна быть простой.

Если новое требование меняет ранее принятое решение, обнови этот документ и связанные спецификации.
