# Черновик REST API (v1)

Все `/api/*` эндпоинты, кроме `health` и `login`, требуют действительной серверной сессии. Изменяющие запросы должны быть защищены от CSRF. В production используем JSON по HTTPS с одним origin для frontend и backend. **Это предварительный контракт**, детали уточняются на соответствующем этапе реализации.

## Авторизация
| Метод | Путь | Тело / назначение |
| --- | --- | --- |
| `POST` | `/api/auth/login` | `{username, password}` → cookie сессии и данные текущего пользователя |
| `POST` | `/api/auth/logout` | Аннулировать сессию |
| `GET` | `/api/auth/me` | Публичные данные текущего пользователя либо `401` |

Публичной регистрации и HTTP API для администрирования пользователей в MVP нет. Учётные записи создаются через CLI.

## Источники
| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/sources` | Только источники текущего пользователя, опционально счётчик `activeTaskCount` |
| `POST` | `/api/sources` | `{name, iconKey}` |
| `PATCH` | `/api/sources/:id` | `{name?, iconKey?}` |
| `DELETE` | `/api/sources/:id` | `204` при успехе либо `409`, если источник связан с задачами |

ID источника создаёт сервер. Поле `iconKey` проверяется по реестру допустимых иконок приложения. Изменение названия или иконки источника отражается на всех задачах его владельца.

## Задачи
| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/tasks` | Получить задачи текущего пользователя с фильтрацией/сортировкой |
| `GET` | `/api/tasks/:id` | Получить свою задачу либо `404` |
| `POST` | `/api/tasks` | Создать задачу текущего пользователя |
| `PATCH` | `/api/tasks/:id` | Изменить поля/статус |
| `DELETE` | `/api/tasks/:id` | Удалить свою задачу, ответ `204` |

Предлагаемые параметры `GET /api/tasks`: `q`, `sourceId`, `status`, `sort=deadline`, `order=asc|desc`, `page`, `limit`. При реализации их можно упростить; стабильные DTO описывать в `packages/shared`.

Пример создания задачи:

```json
{
  "title": "Подготовить пресс-релиз",
  "description": "Согласовать с юридическим отделом",
  "sourceId": "6fe71e33-412a-4761-af57-17db6ab875de",
  "sourceUrl": "https://example.org/original-message",
  "status": "new",
  "deadline": "2026-12-01"
}
```

- `userId` нельзя передавать как поле, определяющее владельца: он назначается из сессии.
- При создании `status` можно не указывать; используется `new`.
- Временные метки генерирует сервер.
- Пустой или некорректный дедлайн отклоняется; дата в прошлом разрешена.
- Чужие задачи и источники должны выглядеть несуществующими для запрашивающего пользователя.
- Соглашение об ошибках: `400` для невалидных данных (или `422` — выбрать один вариант и придерживаться его), `401` без авторизации, `404` не найдено / не принадлежит пользователю, `409` конфликт удаления источника, `500` без раскрытия внутренних деталей.

## Общие транспортные контракты
В `packages/shared` хранятся Zod-схемы запросов/ответов и экспортируемые типы. Не использовать Drizzle-типы таблиц напрямую как DTO и не отдавать `passwordHash` либо внутренние данные сессии.
