# План разработки — небольшими этапами

> Перед началом следующего этапа запрашивай подтверждение. После изменений сообщай изменённые файлы, запущенные команды, результаты проверок и оставшиеся задачи. Само наличие этого документа **не** означает разрешения реализовать весь проект сразу.

## Этап 0 — основа монорепозитория
- [ ] Корневой `package.json`, закреплённая версия pnpm и `pnpm-workspace.yaml` (`apps/*`, `packages/*`).
- [ ] `apps/web`: стартовый React + TypeScript + Vite.
- [ ] `apps/api`: Express 5 + TypeScript, `GET /api/health`.
- [ ] `packages/shared`: минимальный TS-пакет без зависимостей от БД и Node-only кода.
- [ ] Строгий TypeScript, команды разработки/сборки, ESLint, базовые проверки, `.gitignore`.
- [ ] Проверить локально `pnpm install`, dev-сервер web, API health и общие команды typecheck/build.

**Готово, когда:** оба приложения запускаются независимо, импорт из shared-пакета работает, базовые команды проходят успешно.

## Этап 1 — статический каркас frontend
- [ ] `ConfigProvider` с тёмной темой и русской локалью Ant Design.
- [ ] Структура FSD **только для реально реализуемых частей**.
- [ ] Десктоп: сайдбар источников со счётчиками, шапка, таблица задач на тестовых данных.
- [ ] Пустое состояние, отсутствие результатов и простые состояния загрузки.

**Готово, когда:** исходный десктопный UI в целом соответствует согласованному тёмно-сиреневому стилю.

## Этап 2 — интерактивность на тестовых данных
- [ ] Создание и редактирование через `Drawer`, обязательный дедлайн и валидация.
- [ ] Изменение статуса, поиск, фильтрация по источнику и статусу, сортировка по дедлайну.
- [ ] Создание/редактирование пользовательских источников; запрет удаления используемого источника.
- [ ] Адаптивные карточки задач и меню источников для телефона (**не** откладывать всю адаптацию до релиза).

**Готово, когда:** основные пользовательские сценарии работают с данными в памяти на десктопе и в мобильном разрешении.

## Этап 3 — база данных и API
- [ ] SQLite + Drizzle: схемы и миграции для пользователей, источников, задач, сессий.
- [ ] CLI для первоначального создания пользователя с хешированием пароля; `login/logout/me` и сохраняемые серверные сессии.
- [ ] Middleware безопасности: авторизация, проверка владельца, ограничение частоты входа, стратегия CSRF.
- [ ] CRUD API задач и источников, валидация, поиск, фильтрация, сортировка.
- [ ] HTTP-тесты отказа в доступе к чужим данным и к API без авторизации.

**Готово, когда:** два пользователя не могут обратиться к ресурсам друг друга даже при знании идентификаторов.

## Этап 4 — интеграция frontend и backend
- [ ] Типизированный HTTP-клиент и общие Zod-контракты.
- [ ] Экран входа, клиентские guards только для UX; окончательная проверка прав всегда на API.
- [ ] Подключить задачи/источники к реальному API, обработать ошибки и обновление кеша.
- [ ] Проверить сохранность данных после обновления страницы и перезапуска API.

**Готово, когда:** все основные ручные сценарии работают с реальной постоянной БД.

## Этап 5 — подготовка к эксплуатации и развёртывание
- [ ] Проверить ОС и ARM-окружение Repka Pi 3, оценить потребление памяти в 2 ГиБ.
- [ ] Production-сборки web и API, подходящая устройству конфигурация Compose или системной службы.
- [ ] Единый публичный HTTPS-origin, Cloudflare Tunnel при совместимости, безопасное хранение секретов и reverse proxy.
- [ ] Проверить защиту входа/сессий, тесты изоляции пользователей, безопасное резервное копирование SQLite **и тест восстановления**.
- [ ] CI через GitHub Actions; production-деплой **только после явного разрешения**.
- [ ] Smoke-тест с компьютера и телефона через мобильный интернет.

**Готово, когда:** безопасная приватная эксплуатация возможна, процедура восстановления проверена.

## Первый запрос к Codex
> Изучи `AGENTS.md`, `docs/DECISIONS.md`, `docs/ARCHITECTURE.md` и только этап 0 из `docs/ROADMAP.md`. Реализуй **только этап 0**. До изменений покажи короткий план. Не начинай UI и базу данных. После работы сообщи изменённые файлы и результаты команд проверки. Отвечай по-русски.
