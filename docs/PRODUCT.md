# ShitTracker — продуктовые требования к MVP

## Цель
Пользователь вручную переносит в единый личный список задачи, поступающие через Telegram, Jira, Mattermost, почту, встречи и другие каналы. В приложении можно быстро находить задачи по источнику и статусу, менять их состояние и параметры, видеть предстоящие и просроченные дедлайны. При наличии нескольких учётных записей данные каждого пользователя полностью изолированы.

## Пользователи
- Основной пользователь: PR-/коммуникационный специалист, работающий одновременно в нескольких информационных каналах.
- Дополнительные пользователи: коллеги, у каждого из которых собственные приватные задачи; совместной работы и назначения задач нет.
- Администратор сервера: создаёт учётные записи через CLI; формы регистрации нет.

## Основные пользовательские сценарии
1. **Первый вход.** Если у пользователя ещё нет источников, предложить добавить первый источник. После этого становится доступно создание задачи.
2. **Добавление задачи из сообщения.** Нажать «Новая задача», указать название (обязательно), описание (необязательно), источник (обязательно), ссылку на исходное сообщение (необязательно), статус (по умолчанию `new`) и дедлайн (обязательно); сохранить. Приложение **не загружает** содержимое по исходной ссылке.
3. **Просмотр нагрузки.** Открыть задачи, выбрать источник в левом сайдбаре, найти по названию/описанию, отфильтровать по статусу и отсортировать по дедлайну.
4. **Работа с задачей.** Поменять статус прямо в списке или открыть боковую панель для редактирования остальных полей. Разрешён переход между любыми статусами; автоматического продвижения нет.
5. **Завершение.** Установить `done`. Выполненные задачи остаются в списке, если не скрыты фильтрами, и не подсвечиваются как просроченные.
6. **Источники.** Создать источник с названием и иконкой, изменить его, увидеть количество незавершённых задач; запрещено удалять источник, если с ним связана хотя бы одна задача.
7. **Телефон.** Открыть приложение по HTTPS через мобильный интернет, пользоваться карточками задач и полноэкранной формой создания/изменения.
8. **Выход.** Завершить серверную сессию; защищённые данные становятся недоступны до нового входа.

## Поля задачи
| Поле | Требование |
| --- | --- |
| `id` | Постоянный UUID, генерируется сервером |
| `userId` | Владелец из серверной сессии; клиент не может задавать это поле |
| `title` | Обязательно; обрезать пробелы по краям; 1–200 символов |
| `description` | Необязательно; первоначальное ограничение — 2000 символов |
| `sourceId` | Обязательный UUID источника текущего пользователя |
| `sourceUrl` | Необязательная корректная ссылка с протоколом `http:` или `https:` |
| `status` | `new`, `in_progress`, `done`; по умолчанию `new` |
| `deadline` | **Обязательная** календарная дата `YYYY-MM-DD`, без времени |
| `createdAt`, `updatedAt` | Временные метки UTC, управляются сервером |

## Правила дедлайна
- При создании и редактировании дедлайн обязателен; пустое поле — ошибка валидации.
- Дату в прошлом можно сохранить, но пользователю показывается предупреждение.
- Задача просрочена, если дедлайн раньше **сегодняшней локальной календарной даты пользователя** и статус отличается от `done`. Формат дат и границы суток должны отображаться согласованно.
- Дедлайн не означает наличие напоминаний или уведомлений.

## Что не входит в MVP
Автоматические интеграции с Jira/Telegram/Mattermost, AI-обработка, назначение исполнителей, совместная работа, рабочие пространства, Kanban, подзадачи, теги, вложения, комментарии, напоминания, UI импорта/экспорта, публичная регистрация, платежи и аналитика. Нет breadcrumbs и переключателей рабочих пространств.

## Критерии готовности релиза
- Пользователи A и B не могут получить доступ к задачам и источникам друг друга даже при знании UUID.
- Создание, редактирование, изменение статуса и удаление работают с ПК и телефона.
- Клиент и сервер валидируют данные, включая обязательный дедлайн.
- Поиск, фильтры и сортировка работают; счётчики в сайдбаре обновляются после изменений.
- Данные сохраняются после перезапуска процесса; анонимные запросы к защищённому API отклоняются.
- Доступ извне организован по HTTPS, вход защищён, резервное копирование и восстановление БД проверены.

## Конфиденциальность
Не загружать автоматически корпоративную переписку и не хранить конфиденциальные данные работодателя на личной инфраструктуре без разрешения. Не записывать в логи пароли, cookie сессий и полные описания чувствительных задач.
